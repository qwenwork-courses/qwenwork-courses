## 第 1 页：封面 【约 0.5 分钟】

各位好，今天聊千问办公的灵魂，Skill 技能与专家套件。认知重塑系列第四讲。前面三讲讲了智能体本质、平台价值、五大场景，今天这块是整套认知框架里最关键的一块。

## 第 2 页：目录 【约 0.5 分钟】

快速过一下系列脉络。第一讲搞清楚了智能体是什么，说白了 AI 不是一个聊天窗口，它是一个能调用工具、执行动作的代理人。第二讲理解了千问办公作为企业级平台的价值，不是把 ChatGPT 套了个壳，而是从工具、接口、插件到 Skill 有一整套能力体系。第三讲看了五个真实场景，合同审查、周报生成、数据分析这些。

今天第四讲要解决一个更底层的问题：千问办公到底靠什么把能力稳定下来、传承下去。答案就是 Skill。

好，我们进正题。

## 第 3 页：什么是 Skill 【约 2 分钟】

"Skill 是千问办公的标准化操作手册，是让 AI 从随机发挥变成稳定可控的核心机制。""掌握 Skill，就掌握了驾驭千问办公的关键。"

Skill 不是给人看的文档，是给 AI 看的说明书。你写一份操作手册放共享盘里，那是给人看的，看不看取决于人。Skill 不一样，直接喂给 AI，AI 拿到就按流程执行，不存在"看了但没照做"的问题。

"从随机发挥变成稳定可控"是核心。大模型本质是概率推测，同样的问题每次回答可能都不一样。闲聊场景无所谓，但企业场景里你不可能接受一份合同审查今天给你五个风险点，明天三个，后天漏掉最关键的那个。Skill 解决的就是这个。

打个比方。你去一家连锁餐厅，不管去哪家分店，同一个菜味道基本一样。为什么，因为有标准食谱。Skill 就是千问办公的标准食谱。厨师换人了，菜还是那个味，流程没变。

还有个点。Skill 让经验不再依赖某个人。你们公司有没有这种情况，老员工走了，他手里那套方法就断了。新人来了重新摸索，半年才摸到七八成。有了 Skill，老员工的方法直接固化下来，新人拿来就能用。

那为什么非得用 Skill 来解决这个问题，不用不行吗？接下来我们聊这个。

---

## 第 4 页：为什么需要 Skill 【约 2 分钟】

刚才说了大模型天生带随机性。Skill 要解决四个核心问题，课件上列了三个关键词：降低随机性、固化实践、稳定可控。我补一个没写上去的，经验传承。

降低随机性很好理解。给 AI 一套固定操作规范，它就不能逾矩，输出被约束在可预期范围内。就像给新员工一份检查清单，照着逐项过，不会漏掉关键步骤。

固化实践这个有意思。不是写一次 Skill 就完事了，每次执行都在积累。哪里不满意改一下，下次就更好。说白了让 AI 每次干活都比上一次强。当然这个"每次比上一次好"不是自动发生的，是你主动优化的结果。

稳定可控是结果。相同输入经过相同流程，拿到可预期的结果。这对企业太重要了，你不能让关键业务依赖"这次 AI 心情好不好"。想象一下，法务团队用 AI 审合同，每次输出格式、深度、风险分级标准都不一样，这工具就没法用。

经验传承是我额外加的。跑顺了一个方法，写成 Skill，直接交给同事，他不用从头摸索。这个价值很多人没意识到，但用过的都知道有多香。

说到特征，Skill 到底有什么特点让它能做到这些？

---

## 第 5 页：Skill 的三大特征 【约 2 分钟】

可控、可复现、可优化。这里有两个类比，特别贴切。

厨师按标准食谱做菜。下限有保障，做出来不会太难吃。上限靠积累，多做几次火候更好，味道就更好。Skill 也是这样，保底质量有，然后可以持续优化。

新员工有岗位操作手册。不用师傅手把手带，按章办事就行。很多公司老员工一走经验就断了。有了 Skill，经验沉淀在流程里，不依赖某个人。

可控是过程由我们建立和控制，可预测、可管理、可迭代。注意"可迭代"这三个字，Skill 不是一成不变的，发现哪里不好改就是了。可复现是不依赖某个人或某个变量，相同环境拿到一致结果。可优化是每次执行只是保底，哪里不满意直接继续优化。

这三个特征是一体的。可控是前提，控制不了过程谈不上复现。可复现是结果，过程可控了自然能复现。可优化是持续改进机制，保证 Skill 不是写死在那里的，越用越好。

好，概念聊完了。很多人其实一直在用千问办公，但用的方式和 Skill 差了一个层次。

---

## 第 6 页：Skill 与 Prompt 的区别 【约 2 分钟】

很多人用千问办公，其实一直在用 Prompt，以为那就是全部了。

Prompt 是什么，一次性指令。你说"帮我总结一下这个文档"，它做了，做完就结束。没有沉淀，下次还得再说一遍。结果也不确定，同样的文档，今天总结成三段，明天五段，后天可能漏掉关键信息。

Skill 不一样。Skill 是可复用的流程资产。你告诉 AI 这类事情该怎么处理，下次只需要说"帮我处理一下"，它就按既定流程执行。

举个例子。用 Prompt 让 AI 审查一份合同，可能给你一堆意见，格式不统一，重点不突出。下次再让它审另一份，又换一种方式。但如果你把审查流程写成 Skill，规定先查什么、再查什么、输出什么格式、风险怎么分级，那每次审查都按这个流程来，结果就是稳定的。

而且 Skill 可以分享。写好了一个合同审查 Skill，发给同事，他装上就能用。Prompt 做不到，你的 Prompt 再好，别人拿过去效果也不一定一样，缺少流程约束。

还有个区别很多人没注意到。Prompt 的效果高度依赖你的表达能力，说得清楚它就做得好，说得模糊就做得烂。Skill 把这种依赖从"人会说"转移到了"流程写得好"。流程写好了，谁用效果都一样。

一句话记住：Prompt 是一次性指令，Skill 是可复用的流程资产。这句话值得记下来。

那 Skill 在千问办公整个能力体系里到底在什么位置？它跟工具、接口、插件是什么关系？接下来我们把这个层级关系理清楚。

---

## 第 7 页：Skill 在千问办公能力体系中的位置 【约 2 分钟】

千问办公的能力自下而上分四层。工具、API 和 MCP、插件、Skill。

最底层是工具。手机、电脑、纸笔，能力基于工具本身的作用。这个没什么好说的，最基础的硬件和软件。

往上是 API 和 MCP。API 是开放接口，有鉴权、有请求、有返回。MCP 把多个 API 封装在一起。你问学生"现在几点了"，这就是一次 API 调用，很简单。MCP 的价值在于把零散的接口组织起来，让 AI 能用统一的方式调用不同的服务。

再往上是插件。多个 MCP、API 和工具组成的场景化功能模块。比如出差规划插件，把天气 MCP、飞猪 MCP、钉钉 API 串在一起，不用一个一个去查。插件解决的是场景问题，把相关能力打包成一个功能。

最上面是 Skill。Skill 是总指挥，规定下层能力怎么用、用什么顺序、产出什么规范。工具是零件，Skill 把零件有序地组装成一台机器。

这个层级关系很多人搞不清楚。一上来就想搞 Skill，但下面的基础没打好。得先有工具，再有接口，再有插件，最后才能用 Skill 把它们调度起来。就像盖房子，地基没打好就想着装修，肯定不行。

好，Skill 上面还有什么？接下来要讲的东西，是 Skill 的"完全体"。

---

## 第 8 页：什么是专家套件 【约 2.5 分钟】

专家套件是 Skill 之上的完整工作方案包。课件上有句话我特别想强调："不是让 AI 连接工具，而是让 AI 具备某个行业岗位的专业能力。"

前面讲的工具、MCP、API 解决的是"AI 能不能碰得到"的问题。专家套件解决的是"AI 懂不懂这一行"的问题。两个完全不同的层次。能碰得到不代表懂，就像你能打开一本法律书，不代表你会打官司。

装上法务套件之后，AI 能逐条审合同并按红黄绿三级给出判断。不是因为多连了几个工具，而是套件里写好了法务这一行的判断标准。什么条款高风险，什么条款可以接受，什么条款需要谈判，都在套件里。

套件里有三部分。快捷命令，对话里输入斜杠直接调用，比如审查合同、NDA 快筛，不用记复杂指令。数据连接，预配好的外部工具连接，开启后直接访问关联数据。知识技能，这是核心，定义 AI 在这个领域的专业知识、方法论和判断标准。

三层封装度是递进的。连接器解决数据通道，技能解决方法论，专家套件把技能、数据、工作流、标准打包成完整方案。越往右越开箱即用。

目前内置套件覆盖法务、财税、投研、产研、营销、教研、电商等岗位，还在持续扩充。课件下面列了那么多，企业法务、合同管理、中国诉讼助手、企业财税、投资银行，都是已经有的。

特别提一下中国诉讼助手，内含 20 项技能。不是随便凑数的，是真正的行业专家把诉讼流程拆解成 20 个标准化操作步骤。AI 装上这个套件，相当于有了一个懂中国诉讼法的助手。


---

## 第 9 页：Skill 与专家套件，什么时候用哪个 【约 2 分钟】

那 Skill 和专家套件到底什么时候用哪个？

不是二选一，是递进关系。课件上的对比表很清晰，我挑几个关键点。

Skill 解决"这件事怎么做"，专家套件解决"全团队怎么统一地做"。一个是方法论单元，一个是完整方案包。Skill 门槛低，个人就能沉淀。专家套件需要行业专家设计完整工作流。Skill 主要是个人用，专家套件是专家配置一次，全员一键安装。

所以路径是什么，先用 Skill 在小范围跑通最佳实践，稳定之后打包成专家套件让全团队复用。探索验证阶段用 Skill，分发推广阶段用专家套件。

这个递进关系很多人搞反了。一上来就想搞套件，结果流程都没跑通，套件里全是问题。正确做法是先用 Skill 把方法跑顺，再考虑套件化。

而且两者不互斥。可以同时用，个人用 Skill 处理日常任务，团队用专家套件统一标准。配合起来效果最好。


---

## 第 10 页：什么样的任务适合做成 Skill 【约 1.5 分钟】

那到底什么任务值得做成 Skill？

三个特征：高频重复、对质量有稳定要求、多人共用。

高频重复就是今天用明天也用，这项工作里要用下一项工作里也要用。这种任务封装成 Skill 回报最高，写一次用很多次。一个月才用一次的任务，投入产出比就不划算了。

对质量有稳定要求，需要规范和过程不断约束它趋近预期结果。合同审查、周报生成、数据清洗，这些都有明确的"好"的标准。写 Skill 的时候把标准固化下来，AI 每次执行都往这个标准靠。

多人共用，我做出来可以分享给你，你在同类工作里直接能用。这个价值在团队里特别明显。一个人写好了，全团队都能用，效率提升是乘法级别的。

不适合的也有两类。一次性任务，复用场景少，封装没意义。强创意任务，本身要的是多元化结果，Skill 天生低随机性，带不动创意度。比如写广告文案，你要的是各种创意方向，Skill 反而会把创意限制住。

## 第 11 页：结语 【约 1 分钟】

今天讲了这么多，核心就一件事：Skill 是千问办公的灵魂。它把 AI 从随机发挥变成稳定可控，把个人经验变成团队资产，把一次性指令变成可复用的流程。

简单回顾一下本讲的主要内容。我们学习了Skill 是什么，为什么需要它，三大特征是什么。然后区分了 Skill 和 Prompt 的本质差异。接着看了 Skill 在能力体系中的位置，工具、API、插件、Skill 四层关系。最后讲了专家套件是什么，它和 Skill 的递进关系，以及什么样的任务适合做成 Skill。

回到课件开头那句话，掌握 Skill，就掌握了驾驭千问办公的关键。

留个思考题。今天回去想想，你的工作里哪些任务是高频重复的，哪些对质量有稳定要求。把这些列出来，就是你可以开始写 Skill 的候选清单。
